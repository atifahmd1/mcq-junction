2. Workstream 1: Real Authentication Contract

The authentication architecture was formally audited to map how Supabase Auth identity tokens bind to application database records, and how administrative authority is enforced:

Key Architectural Safeguards

  • Role Elevation Resistance (src/lib/auth/sync.ts): Proved that syncUserRecord() ignores client-supplied user_metadata.role or forged JWT claims. New accounts unconditionally receive Role.STUDENT. On update, the role column is omitted, guaranteeing that ordinary users cannot elevate their role.
  • Fail-Closed Suspension & Invalidation: assertAdminSession() evaluates both Auth identity state and PostgreSQL state. Corrupted ban timestamps parse fail-closed, blocking access immediately.
  • Outer vs. Inner Access Boundary: The Edge proxy (src/proxy.ts) serves as an outer redirect shield to conserve server resources, while assertAdminSession() enforces cryptographic and database role checks on every Server Action and Server Component render.

7. Operational Guide: How to Start the App & Log In as Development Admin

Follow these exact steps to run the application locally and log in as an administrator without exposing credentials:

Step 1: Start the Local Development Server
npm run dev

The application will start on http://localhost:3000.

Step 2: Bootstrap the Development Administrator Account
node scripts/dev/create-admin.mjs --email admin@mcqjunction.local

The script securely prompts for the account password, displays the masked database connection string, and requests confirmation (yes) before creating the Auth identity and granting role = 'ADMIN' in PostgreSQL.

Step 3: Sign In via Browser

1. Open Google Chrome and navigate to:
http://localhost:3000/auth/signin?next=/admin

2. Enter the credentials:
- Email: admin@mcqjunction.local
- Password: (the password supplied in Step 2)

3. Click Sign In.

4. You will be authenticated and redirected directly to the protected administrative dashboard:
http://localhost:3000/admin

Step 4: Verify Student Access Is Denied (403 Boundary)

Sign in with an ordinary student account and attempt to navigate to http://localhost:3000/admin. The application immediately displays the structured 403 Forbidden security screen, proving role segregation is enforced server-side.
