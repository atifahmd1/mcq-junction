Transaction Pooler Stale Session Context Analysis

In transaction-mode pooling (port 6543), physical PostgreSQL connections are shared among transactions. If application code executes session-level SET commands, that setting persists on the physical connection across subsequent transactions unless explicitly reset.

Security Isolation Mandate: Next.js Server Actions must supply p_admin_user_id as an explicit parameter directly to fn_publish_exam_paper(paper_id, admin_id) rather than relying on session-level SET. In migration.sql, Guard 0.4 checks if mcqj.caller_user_id differs from p_admin_user_id and raises MCQJ-ERR-5015: Caller identity mismatch, preventing stale connection context from compromising execution. This was empirically verified in DB-18.11.

Public PostgREST Surface Exposure Trade-Off

In migration.sql, GRANT EXECUTE ON FUNCTION ... TO authenticated exposes publication and re-evaluation endpoints on the public PostgREST HTTP gateway. While Guard 0.2 verifies ADMIN role and rejects non-admins, Next.js Server Actions execute server-side via direct connection (DATABASE_URL). Direct client RPC is not required.

Phase 4 Module 1 Hardening Recommendation: Revoke EXECUTE from authenticated in Phase 4 Module 1, reserving execute grants strictly to service_role and direct superuser/owner (postgres). This completely eliminates administrative stored procedures from PostgREST's public surface.

6. Phase 4 Module 1 Implementation Checklist

The functions assertAdminSession() and publishExamPaperAction() do not yet exist in src/. They must be constructed during Phase 4 Module 1 adhering strictly to this checklist:

  • Server-Side Session Verification: Use supabase.auth.getUser() in assertAdminSession(); never trust unverified getSession() cookies.
  • Account Suspension Check: Verify user.banned_until is null or expired.
  • Database Role Verification: Query prisma.user.findUnique and assert role === 'ADMIN'.
  • Direct Parameter Passing: Supply admin.id directly as the explicit parameter to fn_publish_exam_paper; forbid session-level SET mcqj.caller_user_id.
  • Public Surface Hardening: Revoke execute on administrative procedures from authenticated role in Phase 4 migration.
  • Input Validation & Sanitization: Validate all paper UUIDs and input payloads using Zod schemas.
  • Error Masking: Catch database exceptions and strip connection internals from user-facing responses.
