2. Deep-Dive Security Audit (SEC-01 & SEC-02)

2.1 SEC-01: search_path Lockdown & Least Privilege

In PostgreSQL SECURITY DEFINER routines, omitting an explicit search path allows schema-poisoning vulnerabilities. We implemented and verified:

  • Fixed Search Path: Enforced SET search_path = public, pg_temp; across all SECURITY DEFINER functions.
  • Catalog Qualification: System functions qualified as pg_catalog.current_setting(), pg_catalog.hashtext(), and pg_catalog.clock_timestamp().
  • Privilege Revocation: Revoked all execution privileges on publication procedures from PUBLIC and anon; granted strictly to authenticated and service_role.

2.2 SEC-02: Cryptographic Caller Authorization & Anti-Spoofing (Gate 0)

In multi-tenant PostgREST environments, functions accepting an admin ID parameter (p_admin_user_id) can be invoked maliciously by students spoofing an administrator's UUID. We engineered a tamper-proof Gate 0 identity resolution mechanism:

3. Relational Integrity Bug Discovery & Resolution

The Discovered Defect

During test execution of DB-06, a relational gap was uncovered. In booklet_option_mappings, foreign key fk_bom_source_option references question_options(id). Because options are normalized under translations (representations) rather than storing redundant occurrence_id or paper_id columns, a standard foreign key cannot verify that a source option belongs to the question mapped by the booklet.

When test DB-06 mapped an option belonging to Paper 2 into a booklet question of Paper 1, PostgreSQL accepted the insert.

The Fix: Occurrence Integrity Trigger

We added fn_guard_booklet_option_mapping_integrity() and trigger trg_booklet_option_mapping_integrity in migration.sql to inspect and enforce occurrence equality before insert or update: 

CREATE OR REPLACE FUNCTION fn_guard_booklet_option_mapping_integrity()
RETURNS TRIGGER
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = public, pg_temp
AS $$
DECLARE
    v_target_occurrence_id UUID;
    v_source_occurrence_id UUID;
BEGIN
    SELECT occurrence_id INTO v_target_occurrence_id
    FROM booklet_question_mappings
    WHERE id = NEW.question_mapping_id;

    SELECT sqr.occurrence_id INTO v_source_occurrence_id
    FROM question_options qo
    JOIN source_question_representations sqr ON sqr.id = qo.representation_id
    WHERE qo.id = NEW.source_option_id;

    IF v_target_occurrence_id IS NOT NULL AND v_source_occurrence_id IS NOT NULL THEN
        IF v_target_occurrence_id <> v_source_occurrence_id THEN
            RAISE EXCEPTION 'MCQJ-ERR-4007: Option % belongs to occurrence %, cannot map to question mapping % (occurrence %)',
                NEW.source_option_id, v_source_occurrence_id, NEW.question_mapping_id, v_target_occurrence_id;
        END IF;
    END IF;

    RETURN NEW;
END;
$$;

CREATE TRIGGER trg_booklet_option_mapping_integrity
BEFORE INSERT OR UPDATE ON "booklet_option_mappings"
FOR EACH ROW EXECUTE FUNCTION fn_guard_booklet_option_mapping_integrity();

4. Test Harness Hardening & Fail-Closed Safety

To eliminate misleading test results and prevent transaction poisoning:

  • PostgreSQL Savepoints: Wrapped each negative assertion in multi-step tests (DB-06, DB-11, DB-13, DB-17) inside SAVEPOINT and ROLLBACK TO SAVEPOINT blocks. This prevents PostgreSQL error 25P02: current transaction is aborted from cascading to subsequent assertions.
  • Fail-Closed URL Verification: The test runner immediately throws a fatal exception and exits with code 1 if TEST_DATABASE_URL is omitted or does not target 127.0.0.1:5433/mcq_junction_test.
