3. Critical Concurrency & Durability Hardening

Atomic Version-Predicate CAS in Answer Persistence

To prevent concurrent client requests or network retries from overwriting newer candidate inputs with stale data, saveAttemptAnswer uses an atomic conditional update predicate:

const updated = await db.attemptResponse.updateMany({ where: { id: existing.id, version: input.clientVersion, }, data: { selectedSourceOptionIds: input.selectedSourceOptionIds ?? [], displayOptionLabels: input.displayOptionLabels ?? [], numericalInput: input.numericalInput ?? null, isMarkedForReview: Boolean(input.isMarkedForReview), version: nextVersion, answeredAt, }, }); if (updated.count === 0) { return { success: false, occurrenceId: input.occurrenceId, status: "STALE_REJECTED", error: "MCQJ-ERR-6001: Concurrent modification conflict. Stored version differs from client version.", code: "VERSION_CONFLICT", }; }

Concurrent first-time answer inserts are guarded against race conditions by the database unique constraint uk_response_attempt_occurrence, catching Prisma P2002 collisions safely.

Strict Server-Side Expiration & Autonomous Sweeps

Examinations enforce strict zero-grace deadline validation. Once now() > expires_at, any late answer mutation is blocked with MCQJ-ERR-6003 (403 Forbidden). To ensure abandoned tests are finalized, the finalizeOverdueAttempts() background sweep scans for overdue sessions and triggers authoritative scoring.
